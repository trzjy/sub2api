导入引擎是**通用解析器 + 每平台映射器**；映射器状态三态：

| 状态 | 含义 | 当前平台 |

| `enabled` | 已有真实导出 fixture，字段映射已核对，可导入 | **（当前为空——见下：codebuddy 系三平台待含账号 fixture 落盘后启用）** |
| `pending` | 站点有对应平台，但**尚无真实导出样本**，字段映射未核对 | **codebuddy_cn / codebuddy / workbuddy → `codebuddy`（cn/intl/cn）**、codex→openai、codex_api_service→openai、claude_manager→anthropic、antigravity(_ide)→antigravity、grok→grok |

**codebuddy 系三平台的 fixture 取证现状（2026-09-28 实测，钉死为 pending）**：
本机 Cockpit 自动备份（`~/.antigravity_cockpit/backups/cockpit_auto_backup_full_2026-09-28_05-07-25.zip`，
zip sha256 `433c6aaa2a9f4dc7254c6971fbf83d04e0e42e0eedbcd6d5645bba6f5b43a52f`，
backup.json sha256 `c72c5393eb1f33eb17f195cc8d13e140c4396b3e4f82081817f6a8d0d5e7ec47`）
证实**信封契约**：`schema="cockpit-tools.data-transfer"`、`version=1`、顶层键
`schema/version/exported_at/sections/accounts/config`、`accounts.platforms.<slug>` =
`{account_count:int, exported_data:list}`——此信封层契约可复核。但该备份中三平台
`exported_data` 为**空列表**（account_count=0），且本机账号落盘为 AES-256-GCM

**逐账号字段结构（exported_data 条目形状）尚无真实样本可核**。故三平台
**保持 pending**：B1 前置 = 在账号所在机器用 Cockpit 生成含真实账号的导出 →
脱敏 fixture 归档证据目录 + 哈希登记于此 → 逐字段核对 §1.3 映射 → 定向测试

不是实现依据；B1 的 codebuddy 映射器在 enabled 前不实现、不合入。**

规则：
- **pending → enabled 的唯一路径**：取得该平台真实导出文件 → 逐字段核对后在本表
  登记映射与脱敏 fixture → 定向测试通过 → 状态改 enabled。**禁止在没有样本时
  凭协议猜测实现字段映射**（零假设红线：外部文件格式是外部事实，不是可推导项）。
  **enabled 平台的不可变 fixture 契约（钉死）**：每个 enabled 条目必须登记
  **真实 fixture 的归档路径 + 内容哈希**（脱敏归档于证据目录，哈希钉住其
  不可变性）与 `exported_data` 的**完整提取契约**——账户枚举结构
  （accounts.platforms.<slug>.exported_data 的容器形态）、字段类型、嵌套
  路径、规范化规则（别名归一/空白/大小写）；契约未登记完整前该平台
  **保持 pending**，不得启用导入。执行者不从此方案之外猜测账户形状。
  **提交链装载（v16 登记）**：映射器交付时随同闭合"解析条目→载荷"的提交链
  装载；在此之前，若解析结果存在 enabled 平台条目而提交链无可用载荷 →
  **显式错误失败关闭，禁止静默 created=0**（假完成面）。
- pending 平台在预览中显示"已识别 N 个账号，待字段映射核对，未导入"，
  不报错、不静默、不计入失败。
- unsupported 平台显示"暂无对应平台"；**未知 slug（Cockpit 未来新增）**按
  unsupported 处理并在结果中单独计数上报（`unknown_platform_accounts`）。
- slug→平台映射与三态表是唯一映射源（domain 层常量表），加平台只改这张表。

### 1.3 codebuddy 系字段映射（候选对照——三平台 pending，fixture 落盘核对后才可作为实现依据）

> 状态说明（§1.2 取证现状的延伸）：本表为**候选映射对照表**，B1 的
> codebuddy 映射器实现与定向测试必须以"含真实账号导出 fixture + 逐字段
> 核对记录"为前提（§1.2）；fixture 未落盘前本表不构成实现授权。

| Cockpit 字段 | 站点账号字段 | 说明 |
|---|---|---|
| access_token / accessToken | credentials.access_token | |
| refresh_token / refreshToken | credentials.refresh_token | |
| expires_at / expiresAt | credentials.expires_at | **单位 B1 前置钉死**，见下 |
| uid / account.id | credentials.uid | X-User-Id 头来源 |
| enterprise_id / enterpriseId | credentials.enterprise_id | |
| domain | credentials.domain | X-Domain 头来源 |
| nickname / label | name | 重名自动加后缀 |
| slug 推断 | site | `codebuddy_cn`→cn，`codebuddy`→intl，`workbuddy`→cn |
| token_type | （固定 Bearer） | |

- **expires_at 单位（B1 前置验收项）**：B1 开工第一步——用首个真实导出 fixture
  核对源单位（秒或毫秒），钉死"源单位 → 站点毫秒"的唯一换算，连同边界值
  （0、负数、>2286 年）写为定向测试。**单位无法从 fixture 判定时拒绝导入该
  条目**（失败关闭，禁止猜错单位造成"立即过期"或"千年有效"）。
- **必填校验与规范化规则（钉死，preview 与 commit 同一实现）**：
  - **字符串规范化**：所有导入字符串字段先做 `trim`（去除首尾 ASCII 空白）；
    **token/uid/domain 不做大小写归一**（区分大小写原样保留），`slug` 按小写
    精确匹配映射表。空字符串规范化后按缺失处理。
  - **类型契约（钉死，v16）**：`access_token`/`refresh_token`/`uid`/`domain`/
    `enterprise_id` 在导入 JSON 中**只接受 JSON 字符串**——数字/布尔等非字符串
    值一律计入 `invalid_entries`（禁止任何数值→字符串强转，防止数值型"凭证"
    被静默接受）；`expires_at` 单独按有限数值解析，不经字符串路径。
  - **非法值判定**：`access_token`/`refresh_token` 非空、长度 ≤ 8192、
    仅含 ASCII 可打印字符（0x21–0x7E，禁止空白与控制字符）；`uid` 非空、
    长度 ≤ 128、仅含 `[0-9a-zA-Z_-]`；`domain` 为空允许（空 domain 占位
    规则唯一例外），非空时长度 ≤ 253、仅含 ASCII 主机名字符
    （`[0-9a-zA-Z.-]`，禁止空白与控制字符）；`expires_at` 为有限数值。
    任一不满足 → 条目计入 `invalid_entries`，不写入。
  - **唯一索引输入 = 规范化后的值**：`(platform, uid)` 冲突判定、DB 写入、
    幂等比较一律使用规范化后值（保证等价输入不产生双键）。无法满足规则的
    条目失败关闭，无兜底默认值。

### 1.4 导入输入校验边界（preview 与 commit 共用同一解析器）

1. 仅接受 application/json（单文件）或 zip（Cockpit 导出包）；zip 只承认首个
   名为 `backup.json` 的条目——**拒绝一切路径穿越（`..`、绝对路径）、符号链接、
   多条目同名**。JSON 形态**仅接受单个完整 JSON 值**：首个值解码成功后若仍存在
   任何非空白尾随内容 → `PAYLOAD_STRUCTURE_LIMIT` 失败关闭（拒绝尾随数据注入）；
   解码器语法错误统一映射为该错误码，禁止把底层 decoder 错误裸返出统一
   `*CockpitImportError` 契约之外。
2. 大小上限：上传 ≤ 10 MB；backup.json 解析后 ≤ 50 MB；超限失败关闭。
   **ZIP 解压前资源硬上限（阻断项，全部在任何解析或内存分配前检查）**：
   流式逐条目读取（不整包解压）；单条目未压缩字节 ≤ 50 MB；解压总未压缩
   字节 ≤ 60 MB；条目数 ≤ 1000；任一超限立即 `UNARCHIVE_RESOURCE_LIMIT`
   失败关闭，不依赖解压完成后的解析大小检查——防解压炸弹（小压缩包高
   解压放大比）。
   **JSON 结构上限（与字节上限并行，ZIP 门控不覆盖合法大小内的攻击面）**：
   账户条目数 ≤ 200；JSON 最大嵌套深度 ≤ 32；单字段值长度 ≤ 64 KB——
   流式解析阶段逐项检查，超限立即 `PAYLOAD_STRUCTURE_LIMIT` 失败关闭，
   不先物化全部账户（防高 CPU/DB 写入放大/解析器栈耗尽）。
3. **schema 版本白名单**：`schema == "cockpit-tools.data-transfer"` 且
   `version == 1` 才进入解析；其余一切版本（0、负数、2+、缺失）统一
   `SCHEMA_VERSION_UNSUPPORTED` 失败关闭。定向测试覆盖 0/负数/缺失/2。
4. **重复键与冲突别名拒绝**：解析器拒绝同一 JSON 对象内重复键
   （`DUPLICATE_JSON_KEY`，该条目 invalid_entries）；同一逻辑字段的多别名
   （access_token/accessToken、refresh_token/refreshToken、uid/account.id、
   enterprise_id/enterpriseId、expires_at/expiresAt）同时出现时，规范化后
   完全一致才接受，不一致 → 该条目 invalid_entries（`ALIAS_CONFLICT`），
   **不写入、解析器覆盖顺序不决定实际凭证**。
5. 任何条目解析错误不阻断其它平台条目（逐条计数），但凭证材料
   （token/key/secret 字段）**绝不入审计与日志**——日志只含计数、slug、
   uid 哈希前 8 位（§1.7 负向验收）。
6. 临时文件用后即删（defer 清理），不落长期路径。

### 1.5 preview / commit 绑定（服务端签名凭证 + 无状态摘要，多实例安全）

- **preview**：解析前先计算**原始上传字节流的 SHA-256**（`raw_sha256`，覆盖
  含凭证在内的完整文件内容），随解析摘要（逐平台计数）一并返回
  **服务端签名的无状态 preview 凭证**：HMAC（站点既有密钥派生专用 key）
  签名载荷 = **操作者主体 + raw_sha256 + 解析器/映射版本号 + 签发时间
  + TTL（15 分钟）**——凭证无服务端存储（多实例安全），但由服务端签发，
  客户端无法伪造或复用到其它文件/其它操作者。
- **commit**：请求必须携带**preview 凭证 + 原文件内容**；服务端验证签名、
  **操作者主体一致、未过期、解析器版本未变**，再重算原始字节流 SHA-256
  与凭证内 `raw_sha256` 比对，任一不满足 → 失败关闭（签名无效/过期
  `PREVIEW_RECEIPT_INVALID`；摘要不一致 `MANIFEST_MISMATCH`）；全部通过
  才以凭证内版本号的同一解析器解析并执行导入。**禁止无凭证直接 commit**
  （客户端自报摘要不构成绑定——任何持写权限者可自算摘要跳过 preview，
  滚动发布期不同解析器版本也会对同一摘要产生不同导入结果）。
  **提交边界结构强制（v16）**：凭证校验是唯一提交入口的前置——载荷写入
  路径不暴露为可绕过凭证校验的导出方法（私有内部路径，仅校验通过后可达；
  服务构造器不提供无凭证旁路形态，测试替身不得构成生产可复用的第二入口）。
- 服务端**不保存任何 manifest 状态**（无内存缓存、无共享存储依赖）——绑定
  由"服务端签名凭证 + commit 重验证重解析"达成，preview 与 commit 落到
  任一实例行为一致。preview 无副作用；commit 幂等性由 §1.6 唯一约束兜底。
- preview/commit 响应与审计**不返回、不记录任何凭证材料**（含 raw_sha256 之外
  的文件内容片段）。
- **preview 资源消耗边界（B1 前钉死）**：preview 虽为读权限无副作用端点，
  但对上传内容执行 SHA-256、流式解压与 ≤50MB JSON 解析——**沿用既有
  admin 路由的限流/并发控制能力**：单主体 preview 请求速率上限、并发解析
  上限、单请求解析时限（超时失败关闭返回明确错误；**解析器响应 context
  取消——超时/客户端断开即终止解析并释放输入字节，不得留下持有完整上传
  的失控解析协程**，v16）、拒绝计数指标
  （`preview_rejected_rate_limited` / `preview_rejected_concurrency` /
  `preview_parse_timeout`）纳入部署后观测。**B1 开工前取证**：站点既有
  admin 路由是否已具备限流/并发控制——具备则登记复用证据；不具备则
  该边界作为 B1 交付范围补齐（**不得仅依赖文件大小上限**）。

### 1.8 接口认证授权边界

preview 与 commit 统一挂在**既有 admin 账号管理路由组**
（`/api/v1/admin/accounts/*`，沿用站点现有管理员认证中间件与审计主体记录），
不新开端口、不新增认证机制；审计记录操作者主体 + 逐平台计数（凭证材料
照 §1.4-5 零记录）。

**权限能力钉死（两个端点分别绑定既有权限，不复用同一声明）**：

- **commit**：绑定**既有账号管理写权限**（站点现有"账号创建/修改"同款
  capability——提交凭证即创建账号，权限不低于创建账号本身）。
- **preview**：绑定**既有账号管理读权限**（最小权限，preview 无副作用）。
- **write-only 组合判定（B1 前钉死，不留 addendum 待定）**：仅持写权限、
  不持读权限的主体调 preview → **拒绝**（preview 挂读能力是钉死语义，
  站点 capability 矩阵若读写互不蕴含则天然成立；若实测发现既有矩阵
  写蕴含读，则 preview 对该主体放行并在 addendum 登记矩阵证据——两种
  结果都以 B1 开工前的矩阵取证为准，实现不得自行选择）。

B1 验收必含**权限组合矩阵负向用例**（四组合，均断言拒绝响应不含文件
内容片段）：未认证 → 双端点拒；仅读 → preview 过 / commit 拒；仅写 →
preview 按 write-only 判定 / commit 过；读写全 → 双端点过。

### 1.6 并发幂等：数据库唯一约束闭合

- `accounts` 表新增部分唯一索引：`(platform, uid)` WHERE uid != ''（迁移文件
  登记；存量数据先查重，冲突存量人工合并后再建索引——迁移脚本需先跑查重
  检查，有冲突则中止并报告）。
- 写入路径：**commit 整文件原子**——先完成整文件解析与逐条校验，再在
  **单一数据库事务**中写入该文件全部有效条目（`INSERT ... ON CONFLICT
  (platform, uid) WHERE uid != '' DO NOTHING`——**冲突目标精确钉死为 §1.6
  部分唯一索引**，禁止无 conflict target 的宽泛 DO NOTHING：其它唯一约束
  （如 name、关联表 FK 级联冲突）的冲突**不得**被吞成 `skipped_existing`，
  一律走非预期数据库错误路径回滚整个 commit 并明确返回失败；ent 侧用
  OnConflict(冲突目标列) + 唯一约束错误双路径判定：ent
  ConstraintError 与底层 pq 23505 需 isUniqueViolation 与 IsConstraintError
  双路径识别，见 §0 内联条款）；**任何非预期数据库错误回滚整个 commit**
  并明确返回失败——禁止部分成功（第 N 条失败留下前 N-1 个账号、重试又把
  已写入条目报成 `skipped_existing`，完成与部分成功不可区分）。
  **同文件内同键凭证冲突（钉死，先于写入分组校验）**：写入前按规范化
  `(platform, uid)` 分组——组内各条目规范化后**完全一致**才确定性去重
  （计 1 条，计数单列 `deduped_same_entries`）；组内任一字段（token/
  refresh_token/expires_at/domain/enterprise_id）不一致 → **该组整体失败
  关闭**，全部条目计入 `invalid_entries`（原因 `conflicting_duplicate_uid`），
  该组一个账号都不写入，结果中明确计数——**最终凭证不得依赖文件内条目
  顺序**。仅 `(platform, uid)` 冲突（对 DB 存量）→ 计入
  `skipped_existing`，稳定返回计数。重复导入同文件零新增，
  并发提交同文件也零新增（约束兜底，不依赖先查后写）。
  **并发提交计数确定性（钉死，v16）**：commit 事务起点对 cockpit 导入提交
  取 `pg_advisory_xact_lock`（固定键）串行化——并发导入竞争方的
  created/skipped 计数确定，不受"插入前后查询竞态"影响（ent 批量
  upsert 不暴露实际插入行数，先查后写差值在并发下不可判定）；
  DO NOTHING 仍是约束兜底，写入语义不变。

### 1.7 凭证日志零泄漏——哨兵负向验收（B1 阻断项）

构造含**唯一哨兵 token**（如 `WBSENTINEL-<random>`）的 fixture，**同一哨兵
同时置于一个有效条目与多种非法条目**（schema 错误、必填缺失、非法
expires_at），**分别以 JSON 与 ZIP 两种形态**跑 preview 与 commit 全链路，
捕获：HTTP 响应体、审计事件、服务端日志（含 debug 级）。断言：

1. 哨兵值在任何输出中零出现（**含成功导入链路**——有效条目走完事务写入
   后同样零出现）；
2. 输出仅含计数、slug、uid 哈希前 8 位。

**日志汇聚链路全盘点（B1 前置阻断项）**：哨兵测试覆盖的不止应用服务
日志——B1 开工第一步盘点生产部署实际链路中的**每一处可能记录请求体的
汇聚点**：HTTP access log、中间件/调试日志、APM/tracing、反向代理日志、
错误采集（Sentry 类）——逐项登记"该点是否记录请求体"；对 preview/commit
两端点**禁用请求体记录或强制字段级脱敏**（配置级整改，证据落盘）；
哨兵负向测试从**真实入口**（经代理/中间件）打到**日志汇聚点输出**，
验证全链路零泄漏，不只在应用服务日志内断言。

断言失败 = B1 不通过。该测试固化为回归测试（哨兵随机，防止快照式假通过）。

   **模型目录失败关闭语义（钉死，B2 验收项）**：
   - **目录来源**：账号级上游 models 端点实时返回集合，站点既有模型目录
     缓存机制（如有）沿用其既有 TTL；**本方案不新建缓存**。

   - **不可用即排除**：目录端点不可达、超时、返回空集合、返回无法判定的
     非集合结构时，**该 codebuddy 账号对该请求不可选**（计入专用过滤统计
     `upstream_catalog_unavailable`），**禁止**按分组名、旧缓存快照、
     空集合=全部通过等任何形式兜底——判定不了就排除，与 §1 失败关闭
     同一语义。
   - **快照后强制重执行（B2 验收项）**：调度快照（§2.1-3）只保存候选
     **超集**（按聚合规则纳入的 codebuddy 账号本身），**不缓存目录判定
     结果**；真正选号前必须按**当前请求模型 + 当前目录状态**重新执行
     逐模型判定——快照命中不豁免，目录不可用时快照命中的账号同样排除
     （失败关闭在最后一道闸门依然生效）。B2 定向测试必含两个回归用例：
     ①快照命中后请求模型不在当前目录 → 不可选；②快照命中后目录不可用
     → 不可选（`upstream_catalog_unavailable`）。
   - **目录判定顺序（钉死）**：先按账号级 `GetMappedModel`（既有，
     account.go:883）把**客户端请求模型名映射为上游模型名**，再以**上游
     名**与目录做**精确比较**——禁止用客户端名直接比目录（别名场景会
     误杀合法账号），也禁止映射后跳过比较。回归测试必含：别名映射 + 目录
     命中（可选）、别名映射后目录未命中（不可选）、未配置映射的直名命中
     与未命中。
   - **目录查询预算（B2 前钉死，防热路径放大）**：单次选号决策内，目录
     查询**总时限 ≤ 300ms**、**并发查询上限 = 4**、**零重试**（超时/失败
     等同不可用，不重试拖住调度）。
     **本轮查询集合（钉死，消除 >4 候选的未定义语义）**：候选 codebuddy
     账号数 > 并发上限时，**固定查询集合 = 按既有调度排序（优先级/权重
     序）的前 4 个候选**；**并列排序 tie-breaker（钉死）**：优先级/权重
     相同时按**账号 ID 升序**唯一稳定排序（复用既有排序若其自身已含
     确定性 tie-breaker 则沿用，B2 取证确认；无保证时补账号 ID）——
     多实例/不同执行计划下前 4 集合逐位一致。**未进入本轮查询的候选
     不静默跳过，显式按 `upstream_catalog_not_probed` 计数排除**（本轮
     不选，非错误态）——语义等价于"本轮目录判定预算只覆盖排序最前的
     4 个候选"，不存在分批第二轮（分批会违反一轮上限与 QPS 上界）。
     被排除账号若因前 4 个全部不可用而成为下一轮选号候选时，按同一

     预算）。
2. **调度过滤**（`openai_account_scheduler.go:1471`）：`platform_mismatch` 判定

### 3.3 存量影子迁移（manifest 驱动，原子可回滚）

1. **盘点**：生成迁移 manifest（落盘 JSON，唯一 ID `mig-<日期>-<序号>`——
   序号用**既有数据库持久化序列**分配（禁止客户端各自取号拼接，禁止
   UUID 替代路径——UUIDv4 不是原子分配机制）；`manifest_id` 在 manifest
   登记表上有 **DB 唯一约束**，登记事务内约束冲突 = 登记失败（绝不重用
   或改写 ID 重试），快照、操作日志、回滚对象按唯一 ID 一一对应），每条
   记录：影子账号 ID、母账号 ID、绑定分组 ID、倍率/优先级/并发数/模型映射
   全量元数据、目标动作。**manifest 归属唯一性预检（阻断项）**：manifest
   登记进执行记录时以**唯一约束校验**影子账号 ID 与母账号 ID 未被其他
   未完结 manifest 占用（重叠/重复 → 拒绝登记并报告，绝不并列执行两份
   触达同一账号的 manifest）；登记后 manifest 内容**不可变**——后续修订
   一律生成新 ID 新版本，旧版本标记 superseded 并绑定于执行记录，快照、
   操作日志、回滚对象按 ID 一一对应可追溯。**母账号快照按唯一母账号保存
   一份**（多影子共享同一母账号时绝不逐条重复保存执行前状态），含该母账号
   迁移前完整绑定与元数据 + 有序操作日志。**元数据逐项转移**：影子每项
   设置都有明确归属（写入母账号或丢弃——丢弃项逐条给出理由，如"影子级
   模型映射与分组模型清单重复"）。**同母账号多影子的字段冲突**：多个影子
   对同一字段（倍率/优先级/并发数等）给出不同目标值时，**禁止按条目顺序
   自动合并**——该母账号整体阻断，输出冲突字段清单报用户裁定后更新
   manifest 再执行（新 manifest ID）。**未裁定冲突硬阻断（C2 轮钉死）**：
   存在未裁定、待定或互相矛盾的冲突清单时，该母账号的 manifest 迁移
   **与后续影子记录删除**一律失败关闭——每个冲突必须有明确的已接受裁定
   记录才可继续，禁止带映射歧义进入删除阶段。**快照凭证隔离**：manifest、母账号
   执行前快照、影子删除前归档的 schema **只含账号 ID、绑定关系与非秘密
   元数据**，凭证字段（token/key/secret）一律排除（影子无自有凭证、
   母账号凭证不进快照——回滚不需要凭证材料，凭证始终以站点既有加密存储
   为准）；归档落盘前跑凭证扫描（正则扫 token/secret 形态，零命中才归档），
   作为 B3b 验收项。
2. **执行**：**原子执行单元 = 唯一母账号**（非 manifest 条目）——同一
   母账号的全部 manifest 操作在其**单写闸门持有下的单一事务**内应用
   （绑定变更 + 元数据写入原子），事务内与该母账号的**单一执行前快照**
   一次性校验。禁止"逐条一事务"——多影子共享母账号时首条变更会破坏
   后续条目的摘要校验（自相矛盾）。状态摘要不匹配（迁移期间被人工修改
   或另一 manifest 触碰）即阻断该母账号并报告，不覆盖外部变更；同母
   账号的两份 manifest 并发提交时后者因闸门与状态摘要双重拦截自然失败
   关闭。记录逐母账号/逐条状态（pending/done/failed），可重放（failed
   重跑幂等：以最终状态断言而非执行记录）。
   **事务提交后快照刷新（必要步骤，非可选）**：每个母账号事务提交后，
   **复用站点既有调度快照版本/失效机制**（§2.1-3）立即失效并重载该分组
   相关快照——数据库态与实际选号路径不得分叉（快照残留影子账号、或尚
   未含母账号直绑都会造成迁移后选号与库态不一致；删除影子后甚至可能
   继续选到已删除记录；回滚时留下反方向陈旧路由）。**影子记录删除前，
   用新加载快照验证目标状态**（快照中已无影子候选、母账号直绑在位），
   验证失败阻断删除。B3b 测试必含：两个影子共享
   同一母账号的迁移事务（一次提交、一次校验）、并发 manifest 触达同一
   母账号（后者失败关闭）、**迁移提交后快照刷新与删除前快照验证**。
3. **观察窗**（§3.5）达标 → 影子记录删除前全量 JSON 快照归档 → 删除。
4. **回滚路径**（观察窗任一门槛触发即执行）：
   a. 停止迁移后续批次；b. **按唯一母账号的执行前快照 + 有序操作日志严格
   逆序回滚**：每步在事务内校验当前状态与操作日志预期一致（不一致即中止
   并报人工介入），逐条撤销绑定与元数据变更，直至该母账号全部相关影子变更
   一致撤销；c. 影子记录未删除、运行时代码在位（B3a 未删运行时），流量自动
   回落影子路径，**无需任何代码回退**；d. 回滚完成后重查观察窗基线，排查
   根因后重走迁移。
5. **最终删除门槛**：观察窗达标 + 影子快照归档 + 回滚演练完成 + 用户确认，
   四者齐备才执行删除；删除在低峰窗口执行。删除后进入 B3c。
   **删除后可恢复性（B3c 观察期闭合一环）**：影子记录删除 ≠ 迁移
   材料清理——**manifest 与恢复所需最小状态**（母账号执行前/后快照、
   有序操作日志、影子删除前 JSON 快照）作为**迁移权威材料按合同 §4
   临时迁移例外保留**：负责人 = 方案负责人（AI 主会话）、截止 = B3c
   七日延长观察期 + 完整性门槛关闭、清理触发 = 观察期关闭且无未决发现、
   限制 = 材料保留**不作为**完成证明（完成证明仍以 §3.5/§3.6 观测证据
   为准）。**删除后恢复演练（B3c 验收项，一次）**：观察期内用保留材料
   在测试环境完成一次恢复路径演练（manifest + 快照重建影子记录），证明
   删除不使迁移不可逆；演练失败 = B3c 阻断并升级用户裁定。

### 3.5 观察窗量化门槛

- **遥测可重建性前置证明（B3b 阻断项）**：迁移执行前，用站点既有日志/统计
  实际跑出一份**按分组**的基线查询证据，逐项证明以下字段可得：分组维度
  请求成功率、codebuddy 上游 429 计数与占比、5xx/上游错误计数、"无可用账号"
  错误类型、选号次数。**任一字段缺失 → B3b 不开工**（先补观测或登记为环境
  限制报用户裁定，不得用近似统计替代）。
- **基线**：切换前 24h 同分组数据（工作日对工作日，避开明显异常日）。
  **基线有效性门槛（阻断项）**：基线查询逐分组输出**每个指标的分母
  （请求数/样本量）与完整性状态**；任一指标分母为零、样本量不足以计算
  相对阈值（成功率为零样本、429/5xx 基线占比无法按既有数据区分于 0）
  或完整性状态异常 → 该分组**不进入迁移**（B3b 对该分组暂停，观察时钟
  不启动），登记报用户裁定（补流量/延后/人工阈值替代），**不得以 0 基线
  推导"无回滚风险"或按未定义比例放行**。
- **数据完整性门槛**：观察窗内每个分组的遥测查询须满足——采样间隔 ≤ 5 分钟、
  事件覆盖率 ≥ 95%（按既有遥测查询实测）、时间序列缺口 ≤ 10 分钟/小时；
  覆盖不足 → 观察窗**暂停计时**（缺口不计入达标时长），查询自身失败单独
  告警、绝不按零错误计入指标。完整性判定使用与指标同一查询产出（一次
  取证两用），证据落盘。
- **指标与门槛**（按分组统计；**删除放行 = 满足最短观察时长 24h 且累计选号
  ≥ 100 次二者同时成立**——样本量不得单独绕过时长门槛，持续性观测（1h）
  必须完整落在窗口内）：
  **指标统计定义（逐指标钉死，基线与观察窗、B3b 与 B3c 七日观测共用
  同一份查询与定义，任何实现不得另立口径）**：
  - **分组键**：`group_id`，**归因键**：事件记录**同时携带实际承接账号
    ID**（`account_id`）——组级指标用于阈值判定，**账号级归因用于 §3.6
    止损**：组级门槛触发时，按同窗口账号级同一指标**沿门槛恶化方向**
    排出确定性归因序列——**成功率类指标按升序**（最低 = 最劣 = 首位）、
    **429 率/5xx 率/无可用账号等越高越坏指标按降序**（最高 = 最劣 = 首位），
    同值按账号 ID 升序消歧；止损对象 = 归因序列首位。禁止对全部指标
    统一用单一排序方向（成功率降序会把最健康账号排去止损）。无任何账号
    显著劣化（归因不能定位）时**不动账号、整组按用户
    裁定处置**——禁止凭位置或猜测误禁账号。**时间桶**：5 分钟对齐桶
    （UTC，桶边界 `t % 300 == 0`）；一切比率按桶聚合后跨桶再聚合，不做
    跨桶原始事件混算。
  - **账号级归因最小样本（与组级同语义，钉死）**：账号级归因序列仅统计
    观察窗内**自身分母 ≥ 50 次完成请求**的账号——样本不足的账号**不参与
    排序、不作为止损对象**（低流量账号一次失败即成最劣值会被误禁）；
    可参与账号全部样本不足或无账号显著劣化 → 转整组用户裁定。
  - **终态分类（互斥完备，钉死）**：一次完成请求的终态**有且仅有一个**——
    **成功**（复用站点既有终态成功判定：完整重试链内最终响应既非 5xx、
    也非 429、也非上游错误透传）、**最终 429**（最终响应为 429）、
    **5xx/上游错误**（最终响应为 5xx 或上游错误透传）。**最终 429 与
    上游错误不计入成功集合**（否则成功率与 429 率/错误率对同一请求双重
    归类，成功率门槛失真）；三类在证据查询中互斥且可重建（成功 + 最终
    429 + 5xx/上游错误 = 分母）。**429 率分子**随之修正 = 终态为最终 429
    的请求数 + 重试链内中间 429 但最终成功的请求**不计入** 429 率（中间
    尝试由成功定义吸收，只反映最终态）；换号重试链的账号级归因按
    **最后一次实际尝试所用的账号 ID** 记录（事件逐尝试携带，终态归因
    取最后尝试）。
  - **5xx/上游错误率**：分子 = 终态为 **5xx/上游错误**的请求数（§3.5
    终态分类同一互斥集合）；分母同上。重试链内中间失败不计入分子
    （已由成功定义吸收）。
  - **"无可用账号"**：`account_select_failed` 事件计数（按类型细分，
    与既有日志字段一致）。
  - **选号次数**：`account_select` 事件计数（含重试换号）。
  - **最小样本数（可复现门槛）**：回滚阈值比较要求观察窗对应时间桶内
    分组分母 ≥ **50 次完成请求/小时**；低于 50 → 该分组该时段**暂停
    判定并暂停观察时钟**（数据不足不判达标也不判回滚），与基线有效性
    门槛（分母为零/不足 → 不进入迁移）同一语义。
  - 基线与观察窗的证据输出**必须附带上述定义逐项声明与完整性状态**，
    缺任一项 = 查询无效，失败关闭。

  | 指标 | 回滚门槛 |
  |---|---|
  | 分组请求成功率 | 低于基线 2 个百分点，且持续 1 小时以上 |
  | codebuddy 上游 429 率 | 高于基线 1.5 倍，且持续 1 小时以上 |
  | 5xx/上游错误率 | 高于基线 2 倍，且持续 1 小时以上 |
  | "无可用账号"错误 | 切换后出现基线没有的新增类型 |
- 任一门槛触发 → 执行 §3.3-4 回滚；全部门槛未触发且时长 + 样本双门槛满足
  → 放行删除。

### 3.6 B3c 后持续观测与配置级处置 runbook（删除运行时代码后的唯一处置路径）

影子记录删除后保留（复用既有告警通道，不新建机制）：直绑路径按分组的
成功率 / codebuddy 429 / 5xx / "无可用账号" / 选号次数持续观测，固定延长
观察期 **7 天**；任一指标达到 §3.5 回滚门槛同等水位 → 触发下述 runbook。
**七日观测完整性门槛（复用 §3.5，不另立标准）**：沿用 §3.5 的采样间隔、
事件覆盖率、时间序列缺口与查询失败语义——查询失败或覆盖不足 → **暂停
七日计时**（缺口不计入达标时长）并禁止关闭观测，绝不因遥测中断"零指标
越阈"而误判稳定完成；最终完成证据必须**同时包含**指标结果与完整性结果
（时间序列连续性证明）。
**此路径不恢复影子机制（旧链已归零，恢复影子不是选项）**：

1. **止损（执行：值守会话，即时）**：把触发门槛的 codebuddy 账号
   （按 §3.5 账号级归因规则定位）
   `schedulable=false`（或调低其调度优先级至末位），分组流量回落到组内
   原生账号——账号级开关，不需要代码变更。**处置前保存该账号原始调度
   状态**（schedulable/优先级等，写入可重放的处置记录）。
   **止损写入立即失效调度快照（钉死）**：§2.1 调度快照保存候选超集，
   仅写 schedulable/优先级**不等于**止损生效——处置写入（含恢复回写）
   必须复用 §3.3 既有的**快照版本失效/重载机制**使受影响分组的全部
   在存调度快照失效，且**止损宣告生效前必须验证重载后的新快照已排除
   该账号**（验证证据落盘；新快照仍含该账号 = 止损未生效，阻断后续
   步骤并告警）。B2/B3c 定向测试必含：止损写入 → 缓存快照命中路径
   仍不可选中该账号（含快照后强制重执行链路）。
   **归因边界（钉死）**：仅携带**明确单次尝试账号 ID** 的事件（429/5xx/
   上游错误等有实际承接者）可触发账号级止损；`account_select_failed`
   等**无实际承接账号**的选号失败事件为**组级事件，不可账号归因**
   （完整重试链可能涉及多账号，无法稳定归咎单一账号）——只进入整组
   用户裁定路径，**禁止**按归因序列猜测禁用某账号。重试链的账号级
   归因方式以 §3.5"最后一次实际尝试账号 ID"为准。
   **止损/恢复全程持有 §3.3 同款单写闸门**：处置写入与恢复回写用**条件
   更新（CAS）校验当前状态 == 处置记录预期状态**，发现漂移（值守会话、
   管理员或其它任务并发修改）立即中止并升级人工介入——不覆盖外部变更。
2. **恢复已验证直绑态（执行：主会话，1 小时内）**：以 §3.3 迁移 manifest
   为基准核对当前账号/分组配置，人工变更（若有）回退到 manifest 记录的
   已验证形态；**处置前对账号/分组当前配置做 JSON 快照**（登记于证据目录，
   供事后分析）。
3. **止损配置恢复闭环（条件闸门，非自动恢复）**：指标恢复到基线水位后
   （**恢复判定窗口复用 §3.5 完整性门槛**——该 1h 恢复窗口的采样间隔/
   覆盖率/时间序列连续性同 §3.5 标准，完整性不足 → 不恢复、不结束
   处置，绝不把遥测空洞当恢复），**按处置记录将该账号调度配置恢复到
   触发前原始状态**（schedulable/优先级），恢复后进入**复验观察段**：
   完整、可验证的直绑观测（≥ 24h 或覆盖一个完整流量高峰，§3.5 门槛与
   完整性判定同款）——**复发即回闸**：复验段内任一门槛再触发 → 保持
   禁用（schedulable=false）并升级用户裁定（该账号不自动参与后续恢复
   循环，防止"禁用→恢复→复发"抖动）。复验段平稳通过 → 查询验证当前
   配置 == 原始快照，恢复验证证据落盘。恢复验证证据与恢复后稳定性纳入
   完成判据，缺失 = 处置未完成。
4. **完成判据**：连续 1h 指标回到 §3.5 基线水位（含完整性判定）+ 止损
   配置恢复复验段平稳通过 + 处置步骤 1/2/3 的证据落盘；若止损后仍不
   收敛（说明问题不在账号配置而在直绑机制本身），升级为用户裁定项——
   候选动作（临时摘除该分组聚合绑定 / 回退 B2 相关配置）由用户选择，
   不自行扩大处置范围；账号恢复时机与配置随用户裁定一并决定。

### 4.1 分包级积分快照协议（自包含）

- **端点**：`POST https://www.codebuddy.cn/v2/billing/meter/get-user-resource`
  （intl：`https://www.workbuddy.ai` 同路径）。
- **请求头完整契约**（照录，值来源均为账号 credentials/site 表）：
  ```
  Content-Type: application/json
  Accept: application/json, text/plain, */*
  X-Requested-With: XMLHttpRequest
  Origin: https://www.codebuddy.cn            # intl 为 https://www.workbuddy.ai
  Referer: https://www.codebuddy.cn/          # intl 同步换域
  User-Agent: CLI/2.63.2 CodeBuddy/2.63.2
  Authorization: Bearer {access_token}
  X-User-Id: {uid}
  X-Enterprise-Id: {enterprise_id}
  X-Tenant-Id: {enterprise_id}
  X-Domain: {domain}
  ```
- **空 domain 占位规则（照录钉死，唯一例外）**：credentials.domain 为空时，
  chat/billing 出站不发送 `X-Domain` 头，改发占位头
  **`X-No-Authorization: 1`（这是对 §0 通用空值占位规则
  `X-No-<头名>: 1` 的唯一具名例外——上游实测契约即此头名，不按通用
  规则推导出 `X-No-Domain`；通用规则继续覆盖其余空值头）**。B4 定向
  请求测试必含三态：cn（有 domain）、intl（有 domain）、domain 为空
  （占位头形态为 `X-No-Authorization: 1` 而非 `X-No-Domain`），以脱敏
  真实请求 fixture 锁定。
- **响应**：`{code:int, msg:string, data:raw}` 信封，`code != 0` 为业务错误。
  **分包级字段结构尚未取证**——B4 开工第一步是**探针任务**：真实账号抓取一次
  响应（脱敏 fixture 落盘证据目录），把分包条目字段（分包标识/名称/剩余/总量/
  到期时间/**单位**）写入本节 addendum；**字段映射钉死前不写解析代码**。
- **Extra 存储结构**：`codebuddy_credit_packages` =
  `[{id, name, unit, remaining, total, expires_at}]` +
  `codebuddy_credit_packages_updated_at`（**唯一 freshness 依据 =
  最后一次成功快照时间**——**失败写入绝不更新该字段**，只写独立的
  **`codebuddy_credit_error`**（**唯一错误字段名，SSOT**——§4.1 下文
  `codebuddy_quota_error` 废弃不再使用，写入端/UI/审计/回归测试一律
  同名）/ `codebuddy_credit_last_attempt_at`，**成功时间为主排序键的
  全序**：每次抓取附带 **DB 分配的单调版本号**，但**版本号只作同一
  成功时间戳下的确定性次序（tiebreaker，同时间戳按版本号大者胜），
  绝不以版本号新旧否定更晚的成功时间**（先发后至的请求按成功时间
  正常提交）。**成功与失败条件更新使用同一比较器**，比较键 =
  （成功/尝试时间, 版本号）二元组；绝不按到达顺序覆盖。成功与失败
  字段**数据库条件更新**：成功写仅在单调校验通过时原子提交，
  **并在同一事务内清除 `codebuddy_credit_error`——清除条件与成功提交
  使用同一"成功时间优先、版本号仅同时间戳裁决"比较器**（**禁止**对
  清除单独使用版本条件：较早版本的请求较晚成功、其成功时间晚于较新
  版本请求所写错误标记的尝试时间时，快照比较器放行该成功提交而版本
  条件会拒绝清除，造成"最后成功快照 + 过期错误标记"并存的非法状态——
  成功提交与错误清除是同一状态转换，同判同动；失败后再次成功的账号
  不得残留过期错误标记，UI"最后成功快照 + 错误标记"语义与此一致）；
