# 验收清单：福利兑换卡

> 对照 `design.md`。每项需可独立复核的证据（测试输出 / SQL 结果 / 截图），页面可见或接口存在不等于完成。

## 口径回归（对应 design.md 第二节，逐条可验）

- [ ] 卡生成后 24h 内可兑换、超时拒兑（`expires_at` = 生成时刻 + 24h，DB 记录为证）。
- [ ] 同一用户在不同批次各兑一张成功；两张卡的福利余额各自独立计时、独立清零（`welfare_balances` 两行，各自 `expires_at`）。
- [ ] 同一用户同批次兑第二张被拒，返回专用错误码"本批次每人限兑一张"（非 500），并发双开同样被唯一索引拦截。
- [ ] 扣减顺序：存在多行福利余额时，先扣 `expires_at` 最近的行（构造两行不同过期时间，观察扣减顺序）。
- [ ] 随机金额支持两位小数（区间如 1–3 内出现非整数值），分布无明显偏移。
- [ ] 福利兑换不触发返佣；福利消费不出现在返佣/充值统计报表中。

## 功能链路

- [ ] 管理端入口在现有 `/admin/redeem` 页内以 Tab 呈现（福利批次 / 兑换码），未新增侧栏入口；批次列表含已兑/未兑统计，「复制未兑换卡密」输出每行一码纯文本，「导出 CSV」含每卡金额。
- [ ] 管理端可创建批次：分组多选 + 每组天/周/月卡、金额区间（可空）、数量；提交中防双击；批次配置快照可查。
- [ ] 纯订阅卡（无金额区间）与纯余额卡（无分组）与混合卡三种形态均可生成、兑换。
- [ ] 兑换同组订阅已有有效订阅时顺延天数（`AssignOrExtendSubscription` 语义，测试断言 `expires_at` 增量）。
- [ ] 标准分组扣费：先福利后充值；福利不足部分扣 `users.balance`；扣尽的行置 `exhausted`。
- [ ] 充值余额为 0 但福利余额充足时请求预检放行；两者皆空时拒绝。
- [ ] 清零任务：到期行 `amount_remaining=0, status='expired'`；`users.balance` 分文不动；任务重复执行幂等。
- [ ] 已过期但未扫到的福利行不会被扣（扣减 SQL 的 `expires_at > NOW()` 过滤，测试覆盖）。

## 边界（design.md 第五节，确认"不做"未被意外做掉）

- [ ] 批量图片冻结链路仍只走 `users.balance`，未接入福利余额。
- [ ] `user_platform_quotas` 未被改动。
- [ ] 清零 SQL 不含 `users` 表（代码审查确认，非仅测试推断）。

## 迁移与兼容

- [ ] 迁移 245 在真实 PG 上 up/down 各执行一遍通过（参照 244 的 `_test.go` 惯例）。
- [ ] 存量 `redeem_codes` 数据（batch_id 全 NULL）不受部分唯一索引影响，旧类型卡生成/兑换回归通过。
- [ ] 旧余额卡/并发卡/订阅卡的生成、兑换、导出回归通过；返佣钩子条件（redeem_service.go:557）有锁定测试。
