# 优惠情报中心（Promo Intel）

## Why

平台聚合转售业务依赖各厂商的优惠窗口（免费额度、首充/直充折扣、包月订阅首月优惠、价格下调、限时活动、新模型上线），但这些信息散落在几十个厂商的公告/价格/活动页，目前完全靠人工挨个搜索、阅读、验证：

- 每天人工巡查不现实，窗口期短（首月优惠、限时活动）错过即损失；
- CodeBuddy 每日免费额度、DeepSeek 低于官方价的定价、火山首月 49 订阅这类机会，全部是用户事后才得知；
- 厂商页面正文冗长、营销噪音大，人工阅读成本高；
- 已支持的厂商≠情报边界：新厂商/新模型（尚未接入平台的）同样需要被覆盖，情报能力不能依赖现有号池。

## What Changes

新增「优惠情报」后台子系统与 `/api/v1/admin/promo-intel/*` 接口族：

1. **资讯源（promo_intel_sources）**：厂商官方公告/更新日志/价格/活动页的轮询配置（URL、厂商、抓取间隔、启用、可选备注）。内置一批经过可达性与正文可提取性验证的种子源（覆盖国内云厂商大模型平台、模型厂、API 聚合商、编码工具四圈层），管理台可增删改。
2. **每日轮询**：后台单循环（默认每分钟检查到期源），抓取页面 → 剥离 HTML 提取正文 → 内容指纹；指纹未变直接跳过，变化才进入整理层。多实例经 leader lock 防重复。
3. **LLM 整理层**：调用**管理台可配置的独立 OpenAI 兼容端点**（base_url / api_key / model，与系统已支持平台完全解耦，可指向任意新模型或本系统自身网关）按业务定制 prompt 做结构化提取：类型（免费额度/折扣/订阅/价格变动/新模型/新产品/活动/政策）、标题、摘要、优惠力度、有效期、相关性（高/中/低/无关）。无关条目丢弃；LLM 未配置或失败时降级为「原文待整理」入库，恢复后自动补跑，不丢数据。
4. **情报库（promo_intel_items）**：按指纹去重（同一优惠刷新而非重复报），记录厂商、类型、标题、摘要、力度、有效期、原文链接、相关性、状态（待阅/有用/忽略）、发现日期。
5. **汇报**：管理台新增「优惠情报」页——情报列表（筛选+状态分诊）、按日期的每日简报（聚合当日新发现）、资讯源管理（含立即抓取）、整理模型设置（含连通性测试）。

## Capabilities

### New Capabilities

- `promo-intel`: 定义资讯源管理、每日自动轮询、LLM 结构化整理（可配置独立端点）、情报去重入库、状态分诊与每日简报汇报。

## Impact

- **数据库**：新增 `promo_intel_sources` 与 `promo_intel_items` 两表；不修改任何现有表。
- **后端**：新增 repository/service/handler 各一个；后台轮询服务经 Wire 注册（构造即 Start，cleanup 统一 Stop）；外部抓取复用 `internal/pkg/httpclient` 池（超时/响应体上限）；LLM 调用为新增独立 HTTP 客户端（可配置端点，密钥仅存 settings 表、接口回读脱敏）。
- **前端**：新增 `views/admin/PromoIntelView.vue`、`api/admin/promoIntel.ts`、路由、侧栏菜单、zh/en i18n。
- **安全**：抓取仅 GET 无凭证（不含任何账号密钥）；LLM 端点与密钥由管理员显式配置；RSS/正文处理纯本地解析，不执行任何远端指令。
- **多实例**：轮询循环用 Redis leader lock（无 Redis 时单实例直接运行）；LLM 补跑以内容指纹为准，重复执行幂等。

## Non-goals

- 不做开放式全网爬虫/搜索引擎接入（自动发现清单外渠道另行立项）。
- 不覆盖仅发布于微信公众号、无网页版的优惠（清单中标注，后续可评估 RSS/公众号接入）。
- 不自动创建账号/渠道：情报仍是给人看的，动作由管理员决定。
- 不做外部推送（邮件/IM）：简报在管理台页面呈现。
